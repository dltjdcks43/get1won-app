# 기존 구현 리뷰 및 수정 근거

| 기존 문제 | 수정 |
|---|---|
| Profile.ready가 reward/waiting/home/screenB 네 이미지를 필수로 요구하여 사용자 지정 세 항목 요구와 충돌 | A/B/완료 ROI 한 템플릿만 저장. 기존 스키마를 무효화해 남은 이미지가 재사용되지 않음 |
| WAIT_HOME, WAIT_DETAIL 등의 추가 단계와 HOME/B 이미지에 의존 | 요청한 12개 상태로 재구성. 2/3/4 이후는 공통 저해상도 화면 안정 검사 |
| HOME 350ms/B 500ms 기준 이미지 유지 검사 | 실제 화면 변화 관찰 후 250ms 연속 안정. 최대 2초 안에 충족하지 못하면 일시정지 |
| 화면이 변하지 않은 경우와 느린 누적 변화를 따로 검증하지 않음 | 동작 전 기준과 변화 여부, 안정 구간 시작과 누적 차이, 원래 화면 복귀/프레임 공백 검사 |

| 기본 화면에 state enum, raw 좌표, 실행 횟수와 전체 로그가 노출 | 한국어 진행 상태와 완료 횟수만 기본 표시. 내부 값/100개 로그는 고급 정보로 이동 |
| 정지/일시정지 일부 상태에서 generation이 증가하지 않음 | 중지·설정 변경·일시정지 호출도 항상 generation 증가. 이전 화면 선택/시작 준비 및 프레임 무효화 |

| 여러 ROI를 매 프레임 할당하고 Map으로 점수를 관리 | 한 ROI 버퍼와 48×72 화면 버퍼를 재사용. 전체 Bitmap/무거운 라이브러리 없음 |
| 고정 전환 화면 위주 시험으로 500ms 편차 재현 부족 | 실제 움직이는 250~1000ms 전환, 5500~7500ms 완료 표시 편차, 독립 이벤트 오류 카운터 |

cycleId, generation, 단계 비트마스크, acquireLatestImage, MediaProjection 수명주기, AccessibilityService의 GLOBAL_ACTION_BACK은 유지했습니다.

사용자의 후속 정정에 따라 앱 내부 전용 제한은 두지 않았습니다. A/B/ROI를 지정할 때 해당 앱 패키지를 자동 기록하고 그 앱이 전면에 있는지 확인합니다. 내부 테스트 화면은 별도 검증 수단입니다.

첨부 영상의 6100ms 또는 기존 500ms 경험값을 자동화 제어 시간으로 사용하지 않습니다. 6100ms는 테스트 fixture의 완료 표시 생성 옵션에만 존재합니다. 영상에서 식별되지 않은 A/B 좌표나 클릭 번호를 추측해 코드에 넣지 않았습니다.

시각적 안정은 의미상 올바른 목적지임을 보증하지 않습니다. 별도 HOME/B 템플릿 없이 안정성을 판단하라는 요구를 따르는 데 따른 한계이며, 실제 앱 검증 결과와 JVM/에뮬레이터 결과를 혼동하지 않습니다.
