# beta13: simplify POINTS around the accepted observation

Baseline code: beta12 / `16c6af06`; known-best phone behavior: beta8 / `476a6e7d`.
Version: 3.0-beta13 / code 21. No repository reset, main merge or stable tag.

## Direct comparison

Inspected both commits' AutomationService POINTS paths. Beta8 applied clickParent
to the decision target, used a native action when possible, then gestures. Its
global containment fallback could replace OCR text bounds with a promotion
container. Beta9-11 introduced fresh native snapshots, native semantic/context and
balance/withdrawal subtree proof, pausing on failure. Beta12 added another required
screenshot/OCR and eligibility stage. The user's beta12 report shows normal OCR
success followed by fresh_ocr_failed in that extra pipeline.

Those gates can stop before input despite a valid recognized target. This is a
code-level explanation consistent with the reports, not a claim that phone
success rates were measured here.

## Current POINTS flow

1. Use the target generated by the normal observation/Engine decision. No cached
   target, additional native resolution or POINTS OCR request.
2. Check active session/current decision, same package/window, positive dimensions
   and containment in the live window. Changed/unavailable window defers to normal
   observation; the existing package guard still pauses on a different app.
3. Preserve overlay avoidance; movement defers the action and re-observes normally.
4. If that exact Accessibility node is clickable and has its current snapshot
   handle, ACTION_CLICK it. Otherwise gesture at that target's own box center.
   No parent/container search; OCR and synthetic IDs cannot become native handles.
5. Existing Engine observes the result. At most two POINTS submissions per cycle
   (native and gesture combined), with the existing one-second bounded retry and
   a new target from the normal loop. Only actual fresh history confirms success.
   Unknown pages retain bounded pause; no automatic BACK recovery is added.

Removed the extra native snapshot/ancestor collection, native structure approval,
balance/withdrawal proof, dedicated screenshot/OCR, separate eligibility and
gesture retry subsystem. The fresh_ocr_failed POINTS path no longer exists.
Normal HOME OCR/ticket validity, recognition, AD and reward/history BACK remain
unchanged. Engine's only logic change is the POINTS limit from three to two.

PointsTarget and PointsInput are removed from production. Historical copies are
under unit-test sources solely so beta9-12 regression fixtures remain runnable;
they are not included in the APK and do not approve current input. Current routing
is the small PointsDispatch policy used by the service.

## Diagnostics and export

Existing stop summary retained. POINTS logs include input mode, selected bounds,
attempt and history_confirmed/not_confirmed transition, not balances or ad text.
Recent logs now retain 400 chronological physical lines (previously 120 events).
The recent-log dialog copies its full displayed snapshot using ClipboardManager
and the requested toast, or shares it with ACTION_SEND / text/plain through the
system chooser. The last-stop dialog has a copy button. No automatic external send.

reproduction, window deferral, overlay deferral/new observation, callback without
success, fresh history, new-target retry then pause after two, combined attempt

Legacy policy tests are historical fixtures; passing them is not claimed as beta13
