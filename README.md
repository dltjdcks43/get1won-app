# 1원 받기 — 화면 상태 기반 4단계 자동화

Android 14 / 15 / 16(API 34–36), Java 17. 앱 이름은 **1원 받기**입니다. 루팅 없이 AccessibilityService와 MediaProjection을 사용합니다. 사용자가 직접 지정한 외부 앱에서도 실행할 수 있으며 자체 테스트 화면도 포함합니다.

## 설정은 세 가지

1. 사용할 앱을 먼저 열어 두고 이 앱으로 돌아옵니다. 접근성 서비스를 켜고 전체 화면 공유에 동의합니다.
2. **1번 위치 지정**을 누르면 직전 앱으로 돌아가 선택 오버레이가 표시됩니다. A 위치를 한 번 터치합니다.
3. 같은 방식으로 **3번 위치 지정**에서 B를 터치합니다.
4. 실제 완료 표시가 보이는 화면을 준비한 뒤 **완료 표시 영역 지정**에서 완료 글자 전체와 특징을 드래그합니다. 그 영역을 완료 템플릿으로 저장합니다. 대기 표시를 완료 템플릿으로 등록하면 안 됩니다.
5. 대상 앱의 시작 화면을 준비하고 메인에서 반복 횟수와 **시작**을 누릅니다. 자동화는 지정된 앱이 전면에 있고 새 프레임이 도착했을 때 시작합니다.

HOME·B 화면·대기 이미지 등록은 없습니다. 지정한 앱의 패키지는 터치 시 자동으로 기록하므로 사용자가 입력하지 않습니다. 다른 앱에서 새 위치를 지정하거나 해상도/회전이 바뀌면 기존 세 항목을 무효화합니다. 이전 1.0 설정은 새 형식과 호환되지 않아 다시 지정해야 합니다.

플로팅창에는 상태·완료 횟수와 **일시정지/재개, 중지, 위/아래**만 있습니다. 설정 메뉴는 메인 화면에만 있습니다. 내부 상태, generation, 실행 횟수, 최근 100개 로그는 **고급 정보**에만 표시합니다.

## 상태 머신과 실행 조건

`STEP1_TAP → WAIT_COMPLETION → STEP2_BACK → WAIT_STABLE_AFTER_STEP2 → STEP3_TAP → WAIT_STABLE_AFTER_STEP3 → STEP4_BACK → WAIT_STABLE_AFTER_STEP4 → NEXT_CYCLE`

- 1번: 새 화면에서 A를 한 번 터치합니다.
- 2번: 완료 ROI가 처음 유효하게 일치한 프레임의 같은 호출 흐름에서 `GLOBAL_ACTION_BACK`을 요청합니다. 감지 후 예약·delay·다중 프레임 투표가 없습니다.
- 3번: 2번 후 실제 화면 변화와 연속 안정이 확인된 경우에만 B를 한 번 터치합니다.
- 4번: 3번 후 실제 화면 변화와 연속 안정이 확인된 경우에만 `GLOBAL_ACTION_BACK`을 요청합니다.
- 다음 1번: 4번 후 실제 화면 변화와 연속 안정이 확인된 경우에만 시작합니다.
- 완료 대기는 최대 30초, 화면 안정화 대기는 최대 2초입니다. 시간 초과는 PAUSED만 수행하고 BACK/클릭/다음 사이클을 실행하지 않습니다.
- cycleId와 단계별 비트마스크로 각 사이클의 1/2/3/4를 한 번만 실행합니다.
- 일시정지·중지·재시작·설정 변경은 generation을 바꿉니다. 과거 프레임, 제스처 콜백, 화면 선택/시작 준비 작업을 무효화합니다.
- 재개는 새 프레임부터 검사하고 안정 구간을 새로 측정합니다. 중지 후 예약된 3번/4번 실행은 없습니다. 이미 Android에 제출된 1ms 제스처 자체를 소급 취소할 수는 없습니다.

## 완료 감지

`acquireLatestImage()`로 최신 화면만 읽습니다. 등록된 ROI를 160×48 명암값으로 읽어 명암 중심화 상관도와 경계 상관도를 비교합니다. 둘 다 0.96 이상이어야 완료입니다. 단색 템플릿은 거부합니다. 밝기 변화는 허용하지만 다른 글자의 형태는 비교합니다. 전체 화면 OCR, OpenCV, 매 프레임 전체 Bitmap 생성은 없습니다.

접근성 트리에서 실제 보이는 `3초 구경해요` 또는 `3초 구경해주세요` 문구가 있으면 완료 판정보다 차단을 우선합니다. 대기 이미지 등록은 필요 없습니다. 외부 앱이 텍스트를 접근성에 제공하지 않으면 완료 이미지의 특징 구분이 중요합니다.

## 화면 안정화

화면을 48×72 명암 샘플(3,456개 값)로 읽습니다. 상태 표시줄·내비게이션 영역·플로팅창·완료 ROI는 분석에서 제외합니다. 샘플 버퍼는 재사용합니다.

1. 동작 직전 샘플을 메모리에 보관합니다. 현재 화면이 그 기준과 충분히 달라져야 합니다. 클릭/BACK이 무시되어 같은 화면에 머무는 경우는 통과하지 않습니다.
2. 화면을 24개 블록으로 나눠 명암 차이를 비교합니다. 동작 전 대비 블록 변화량이 0.06 이상인 화면에서 안정 검사를 시작합니다.
3. 안정 구간 시작 샘플과 비교한 변화량이 0.012 이하인 상태가 250ms 연속 유지되어야 통과합니다. 이전 한 프레임만 비교하지 않아 느린 애니메이션 변화의 누적도 확인합니다.
4. 프레임 간격이 200ms보다 커지면 연속 안정 시간을 다시 측정합니다. 기준 화면으로 되돌아간 경우도 통과하지 않습니다.
5. 2초 내 조건을 충족하지 못하면 일시정지합니다. 500ms 경과만으로 통과시키지 않습니다.

화면 안정화는 시각적 움직임 종료를 판단하며, 화면 내용의 의미나 목적지가 올바른지까지 증명하지는 않습니다. 같은 앱의 예상 밖 팝업, 움직이는 광고, 일부만 바뀌는 화면 등은 반드시 대상 기기에서 시험해야 합니다. 모든 외부 앱의 무오인식이나 최단 반응 시간을 보장하지 않습니다. ‘추가 대기 없음’과 실제 캡처·연산·OS 처리 시간이 0이라는 것은 다릅니다.

## 자체 시험

메인의 **자체 테스트 → 테스트 준비**로 같은 세 항목을 실제 렌더링 화면에서 자동 등록합니다. 외부 앱 설정은 테스트 설정으로 바뀝니다. 이후 반복 횟수와 **시작**을 선택합니다.

**자체 테스트 → 등장 시간 선택**에서 3000/3500/5000/6100/7000/10000ms, 완료 표시 안 나옴, 매회 5500~7500ms 랜덤을 선택합니다. 이 시간은 테스트 화면에 표시가 나타나는 시간이며 자동화 BACK의 타이머가 아닙니다.

2번 후 전환은 250/400/500/700/1000ms로 변하고, 3번·4번 후 전환은 250~1000ms로 변합니다. 독립적인 화면 이벤트 관찰기가 정상 사이클, 중복 클릭, 빠른 BACK, 순서 오류, 완료 전 BACK, 전환 중 클릭, 중지 후 동작을 셉니다. 50회 또는 100회로 시험할 수 있습니다.

## 빌드와 검증

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew connectedDebugAndroidTest
```

JDK 17, Android SDK 36, Gradle 8.11.1, AGP 8.10.1을 사용합니다. Android Studio에서 이 폴더를 바로 열 수 있습니다. `INTERNET` 권한이 없으며 캡처 화면은 파일로 저장·업로드·전송하지 않습니다. 사용자가 등록한 작은 완료 템플릿과 설정만 앱 내부에 저장합니다. 로그는 메모리에 최근 100개만 유지합니다.

CI는 push/pull_request/workflow_dispatch에서 unit test, lint, assembleDebug를 수행하고 **get1won-debug-apk** artifact에 **app-debug.apk**를 업로드합니다. 별도 기기 테스트는 API 34/35/36 에뮬레이터에서 실제 공유·캡처·터치·BACK으로 무작위 50회 반복과 완료 미등장/중지를 검증합니다. JVM의 무작위 100회 테스트와 실제 Android 통합 테스트 결과는 구분해야 합니다.
