# 1원 받기

Android 14–16(API 34–36), Java 17. 루팅 없이 AccessibilityService와 MediaProjection을 사용합니다.

## 설치 및 설정

GitHub Actions의 `get1won-debug-apk` artifact에서 `app-debug.apk`를 받습니다. Android Studio에서는 이 폴더를 프로젝트로 열고 JDK 17을 사용합니다.

1. 앱의 **접근성 설정**에서 `1원 받기` 서비스를 켭니다. 외부 설치 APK에서 Android가 제한된 설정을 표시하면 앱 정보 화면에서 사용자가 직접 허용해야 합니다.
2. **화면 공유 시작**을 눌러 전체 화면 공유에 동의합니다. 자동 재승인이나 토큰 재사용은 하지 않습니다.
3. 대상 앱으로 이동합니다. 플로팅창의 **영역/위치**에서 A와 B를 각각 탭해서 등록합니다. 메인 화면의 위치 지정 버튼을 사용한 경우에도 대상 화면으로 이동한 뒤 **지정 시작**을 누릅니다.
4. 실제 **1원 받았어요**가 표시된 상태에서 해당 글자와 아이콘을 포함하는 좁은 영역을 드래그해 등록합니다. 배경이나 큰 광고 이미지까지 포함하지 마세요.
5. 다음 상세 진입에서 **3초 구경해요 / 3초 구경해주세요**가 보일 때 **3초 대기 기준 저장**을 누릅니다. 보상과 정확히 같은 영역을 사용하며, 두 이미지가 구별되지 않으면 등록을 거부합니다.
6. HOME에서 화면을 구별하는 고정 제목·아이콘 영역을 **HOME 기준 영역**으로 등록합니다. 포인트 잔액처럼 바뀌는 숫자는 제외합니다.
7. B를 수동으로 열고 전환이 끝난 화면의 고유 제목·아이콘을 **B 화면 기준 영역**으로 등록합니다. HOME과 B가 같은 모양이면 사용할 수 없습니다.
8. HOME으로 돌아와 플로팅창에서 **시작**합니다. 반복은 1/5/10/20/50/무한, 최대 대기는 10/15/30초/제한 없음입니다.

화면 방향·해상도·앱·글꼴 크기를 바꾸면 다시 등록합니다. ROI 또는 좌표와 겹치지 않는 위치로 플로팅창을 배치할 수 없으면 시작하지 않습니다. 등록 이미지와 좌표는 앱 내부 저장소에만 저장하며 인터넷 권한은 없습니다.

## 실행 규칙

`A → 상세/보상 확인 → BACK → HOME 확인 → B → B 화면 확인 → BACK → HOME 확인` 순서입니다.

- 2번 BACK은 첫 유효 보상 프레임에서 동기 호출합니다. `postDelayed`, 추가 100/300/500ms 대기, 다중 보상 프레임 투표는 없습니다.
- 대기 이미지나 접근성 텍스트가 감지되면 BACK을 차단합니다. 두 문구가 함께 감지돼도 차단합니다.
- 보상 문구가 없거나 사라진 것만으로는 절대로 성공 처리하지 않습니다.
- HOME은 350ms, B 화면은 500ms 동안 기준 이미지가 유지되는지 확인합니다. 시간만 지나서는 통과하지 않습니다.
- 4번은 사용자 요구에 명시된 별도 B 화면 복귀 동작입니다. 대기 문구가 감지되면 4번도 차단합니다.
- 타임아웃은 PAUSED 전환만 수행합니다. 프레임 공급이 멈춰도 별도 감시 타이머가 일시정지합니다.
- cycleId와 단계 비트마스크로 중복 실행을 막습니다. 일시정지/중지/재개 시 epoch를 갱신해 과거 프레임과 제스처 콜백을 무시합니다.
- Android에 이미 제출된 1ms 터치 자체는 취소/되돌릴 수 없습니다. 예약된 후속 터치·BACK은 없으며 중지 이후 새 작업을 제출하지 않습니다.
- 재개는 중단된 대기 상태부터 새 프레임으로 확인합니다. 화면을 수동으로 변경해 상태가 맞지 않으면 중지 후 HOME에서 새로 시작하세요.

## 감지 방식과 한계

`acquireLatestImage()`로 최신 프레임만 가져오고, 전체 화면 Bitmap 생성 없이 ROI만 160×48 명암 샘플로 읽습니다. 명암 중심화 상관도와 수평/수직 경계 상관도 둘 다 0.96 이상이어야 보상으로 인정합니다. 대기 기준과의 점수 차이도 0.10 이상이어야 합니다. 단색 영역은 거부합니다. 대기 차단 점수는 0.85입니다. 접근성 텍스트는 대기 차단 보조용으로만 사용하며 보상 승인을 대신하지 않습니다.

ROI 등록은 실제 해당 문구가 표시된 상태에서 해야 합니다. 이미지 매칭으로 모든 외부 앱/광고/테마의 무오인식을 수학적으로 보장할 수는 없습니다. 인식 불가·모호함·공유 중단·화면 크기 변경은 다음 단계로 넘어가지 않고 대기/일시정지합니다. ‘0ms 추가 대기’는 감지 후 의도적 대기가 없다는 뜻이며 화면 캡처·분석·Android 처리 시간은 존재합니다.

## 테스트

앱에서 **테스트 화면 열기 → 테스트 프로필 자동 등록**을 누르면 렌더링된 HOME/보상/대기/B 화면을 실제 MediaProjection으로 등록합니다. 기존 대상 앱 프로필은 테스트 프로필로 교체됩니다. 메인에서 50회와 3000/3500/5000/7000ms를 설정하고 테스트 HOME의 플로팅창에서 시작합니다. **영구 대기**로 보상이 끝내 나타나지 않는 경우도 시험할 수 있습니다. 정상 사이클, 잘못된 1번, 빠른 2번, 누락·중복·순서 오류를 표시합니다.

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew connectedDebugAndroidTest
```

단위 테스트는 네 보상 지연별 50회 순서, 무한 대기, 타임아웃, 첫 프레임 즉시 실행, 중복·과거 이벤트·중지·양쪽 문구 동시 표시 등을 검증합니다. 기기 테스트는 일회용 CI 에뮬레이터에서만 접근성 설정을 활성화하고 실제 공유 동의·ROI 등록·터치·BACK으로 50회를 시험합니다.

CI는 push/pull_request/workflow_dispatch에서 unit test, lint, assembleDebug를 실행하고 APK를 업로드합니다. 이어 API 34/35/36 에뮬레이터 테스트를 실행합니다. 실제 성공 여부는 Actions 실행 결과를 확인해야 하며, 단위 테스트 통과가 외부 앱 실기기 테스트 통과를 뜻하지 않습니다.

## 코드

- `Engine.java`: Android와 분리한 상태 머신 및 동기 효과 게이트
- `CaptureService.java`: 공유 수명주기, 최신 프레임, ROI 분석
- `AutomationService.java`: 제스처/BACK, 접근성 오버레이, 영역 등록
- `TestActivity.java`: 실제 화면 기반 시험 모드

공식 기준: [MediaProjection](https://developer.android.com/media/grow/media-projection), [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [AGP 8.10/API 36](https://developer.android.com/build/releases/agp-8-10-0-release-notes).
